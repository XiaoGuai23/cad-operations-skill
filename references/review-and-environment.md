# 局部核对与环境自检

## 开工前：环境自检

在当前任务目录运行：

```text
python -m cad_skill_core doctor --cache output/cad-environment.json --json
```

分别报告 DXF 编辑、局部检查/渲染、DWG/PDF 环境及原生夹点验证。
这是能力预检，不会启动 AutoCAD，不证明许可证、打印机或交互行为可用。
原生夹点状态始终保留为未验证，直至在任务副本中实测。

原生发现失败会保存原因；程序文件、配置或配套资源改变后重新检查。同一指纹下
24 小时内复用失败证据，避免反复尝试。修复证书、安装或环境后可用 `--refresh`
强制重查。成功发现不免除每次原生启动前的现有签名/身份检查。
`--autocad-path PATH` 指定安装；`--skip-native` 显式跳过原生发现，不能据此称环境通过。
该后端当前验证 AutoCAD 2023；其他版本应走已核实可用的对应路径，不能猜兼容。

## 修改后：局部前后核对

```text
python -m cad_skill_core review BEFORE.dxf AFTER.dxf --out output/local-review --padding 5 --tolerance 0.000001 --json
```

输入应为同一图纸的修改前后版本，单位一致。根据变动对象生成局部区域，相距较远的
修改分开出图；也可显式加 `--box xmin ymin xmax ymax` 限定核对范围。
`--padding` 和 `--tolerance` 使用绘图单位，应按图纸确定；示例值不是工程默认要求。
输出目录必须为新目录。最多自动输出 30 个局部区域，更多时按范围分批。

产物：`index.html`、每个区域的 before/after PNG、`review-report.json`。
左右图坐标范围、画布和比例一致；报告记录源文件哈希、变动句柄、问题位置及检查范围。
命令只读源 CAD，不会自动补线、移动标注或重做填充。

| 候选问题 | 检查方法与边界 |
| --- | --- |
| 新断口 / 相连轮廓被删除 | 比较原来相接的平面直线端点、T 接点及圆弧相切/端点接触；替换线段的端点身份不能一概推断 |
| 重线 | 检查平面直线共线重叠和同圆圆弧重叠；仅端点相接不算重线；区分原有和新增重叠 |
| 填充边界脱离 | 比较原来贴合轮廓的直线/圆弧 HATCH 边界；同时提示填充被删除 |
| 文字与轮廓干涉 | 用 TEXT/MTEXT 及原生标注显示文字的近似包围框找候选，需目视确认 |

诊断覆盖平面 LINE、CIRCLE、ARC、零宽 LWPOLYLINE（含 bulge）及直线/圆弧 HATCH 边界；椭圆、样条或复杂对象
会进入 `coverage.not_analyzed`，不能据此宣布全图无缺陷。曲线仍可能由显示后端渲染，
“能显示”与“已做几何检查”分开记录。字体、显示和打印结果仍可能与原生 CAD 不同。

`needs_review` 表示有新增候选；`checked_with_limits` 表示已执行范围内检查，仍需看图和
处理未支持内容。这些状态不替代已有修订验收与交付状态。命令返回 0 只表示诊断运行完成，
环境可能被阻塞，图纸也可能有候选问题；看 JSON 内容决定下一步。

允许的修改本身也可能产生候选，例如有意开口或删除填充。按批注逐条核对后记录取舍，
不能把所有候选都自动修复。只重跑实际变化或尚未解决的检查项。

跨轮次批注与自动保留旧要求见 [批注台账](comment-ledger.md)。
